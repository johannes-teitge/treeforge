TreeForge ist kein Page Builder. TreeForge ist ein strukturierter Content Explorer.

1. Grundidee

TreeForge verwaltet Inhalte nicht als lose Blöcke auf einer Seite, sondern als strukturierte Nodes in einem Content Tree.

Node

Ein einzelnes Content-Objekt, z. B. Text, Bild, Button, CSS, Markdown oder Columns.

Tree

Nodes können Kinder enthalten. Dadurch entstehen saubere Seitenstrukturen.

Workspace

Draft, Review und Published trennen Bearbeitung, Freigabe und Live-Seite.

Merksatz: Structure first. Content grows in Layers.

2. Aktueller Alpha-Stand

Core

Node-System

Text, Image, Button, CSS, Markdown, Columns und Column als Node-Typen.

Backend

Explorer

Workspace-Spalte, Tree-Spalte, Inspector, Properties, JSON und Preview-Buttons.

Workflow

Draft → Review → Published

Änderungen werden nicht direkt live geschaltet, sondern zuerst geprüft.

Safety

Archive & Rollback

Published-Versionen werden archiviert und können wiederhergestellt werden.

3. Warum der Tree wichtig ist

Bei einer flachen Blockliste sieht TreeForge noch aus wie ein normaler Editor. Der Vorteil wird sichtbar, sobald Nodes verschachtelt werden.

🌳 Startseite ├─ Text ├─ Image ├─ Button └─ Columns ├─ Column │ ├─ Text │ └─ Image └─ Column ├─ Text └─ Button

Dadurch wird klar: TreeForge ist kein klassischer Page Builder, sondern ein strukturierter Content Explorer.

5. Content Workflow

Die Live-Seite bleibt stabil. Änderungen entstehen zuerst im Draft, werden im Review geprüft und danach veröffentlicht.

storage/workspaces/ ├─ draft/pages/home.json ├─ review/pages/home.json ├─ published/pages/home.json └─ archive/pages/home/ ├─ 2026-06-10-001744.json └─ ...

Preview URLs

/ = Published /?workspace=draft = Draft Preview /?workspace=review = Review Preview

6. Git Workflow

Git ist die technische Zeitmaschine für den Code. Jeder stabile Stand wird committed und bei Meilensteinen getaggt.

BefehlBedeutungWann nutzen?
git statusZeigt den aktuellen Zustand.Vor und nach jedem Patch.
php patches/run.phpFührt neue Patches aus.Zum Aktualisieren des Projekts.
git diffZeigt Änderungen.Vor dem Commit prüfen.
git add .Änderungen vormerken.Wenn getestet.
git commit -m "..."Stand speichern.Nach fertiger Etappe.
git tag v0.1.x-alphaVersion markieren.Bei Meilensteinen.

Typische Reihenfolge

git status php patches/run.php git status git add . git commit -m "Add columns tree alpha" git tag v0.1.21-alpha git log --oneline --decorate

7. Patch-Runner

Der Patch-Runner ist unser kleines Update-System. Er führt neue Patch-Dateien aus und merkt sich, welche bereits gelaufen sind.

treeforge/ ├─ patches/ │ ├─ run.php │ ├─ executed.json │ ├─ patch-013-text-node-editing.php │ ├─ patch-014-review-workflow.php │ ├─ patch-015-archive-rollback.php │ ├─ patch-021-columns-tree-alpha.php │ └─ patch-024-css-nodes-as-style.php └─ storage/ ├─ logs/patch-runner.log └─ system/patch-history.json

Regel

Patch ausführen, Browser testen, dann committen. Wenn etwas kaputtgeht, ist der vorherige Git-Stand der sichere Rücksprungpunkt.

8. Tags & Versionen

Ein Tag markiert einen Meilenstein.

git tag v0.1.24-alpha git tag git log --oneline --decorate
TreeForge-Regel: Jeder größere Alpha-Fortschritt bekommt einen Tag.

Alpha-Merksatz

TreeForge bearbeitet nicht live. TreeForge arbeitet in Drafts, prüft in Reviews, veröffentlicht nach Freigabe und kann zurückrollen.
